context-trimmer · turn-window 裁剪策略

一轮 = 连续用户消息 + 回应它们的助手消息（工具循环 + 最终回答）。活跃轮数超过 threshold 时触发裁剪。
裁剪前 整段历史每轮都重复发给模型
TURN-WINDOW TRIM
裁剪后 只发送粘性窗口内的轮次
粘性边界固定在 c − (recentFullTurns + priorTrimmedTurns)，随对话增长保持不动，保证前缀逐字节稳定、不破坏 prompt 缓存。
丢弃区（Dropped）
更早轮次整体丢弃，不再发给模型；完整历史存于本地，可用 context_recall 取回。
面包屑（Breadcrumbs）
丢弃区中靠近边界的 100 条用户消息，每条截断至 100 token，前置到首条保留消息。
裁剪区（priorTrimmedTurns）
只保留用户输入 + 助手最终文本，丢弃中间的工具循环。
完整区（recentFullTurns）
最近几轮完整保留：用户输入 + 工具循环 + 最终回答。
